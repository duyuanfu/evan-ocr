## Context

在目前的版本中，Evan 已经具备了高精度的 RapidOCR 与 WinRT 双 OCR 引擎，能够在毫秒级内准确定位截图中每一行、每一个字符的精确物理与逻辑矩形包围盒。
然而，用户截取画面后经常面临“修改截图中数据、遮蔽或替换错误文本”的诉求（轻量级就地“P图”）。传统操作需要用户用取色器在旁边画矩形遮盖、再手动选字体打字覆盖，繁琐且极易产生明显修图边缘破绽。
本功能设计实现“原位文本感知擦除与无痕替换”系统，让用户能够通过双击原图文字，实现背景毫秒级无痕抹平，并在原位以拟合出的原字体颜色、字号进行原地打字覆盖。

## Goals / Non-Goals

**Goals:**
- **背景内容感知无痕修复 (`ImageInpainter`)**：
  针对选中文本矩形包围盒，基于外扩 2~3px 边缘像素采样与双线性渐变/Telea 填充算法，在 1~3ms 内无痕抹除原字迹，完全适应纯色背景与线性微渐变背景。
- **字体样式与排版参数逆向推断 (`FontAttributeEstimator`)**：
  从待擦除文本框内部像素自动分离前景字符色与背景底色，推算文字颜色（Hex）、估算字号（根据包围盒高度换算）及粗细推荐。
- **矢量标注图元整合 (`InplaceTextEditAnnotation`)**：
  将“修复后的背景贴块”与“新输入的文本”组合为自包含标注图元，支持实时重绘、点击二次编辑、位置微调以及 `Ctrl+Z` 历史撤销。
- **双端交互链路全贯通**：
  - 截屏覆盖层工具栏提供“✏️ 原地文本修改”专用模式；
  - OCR 结果对照弹窗左侧原图支持直接双击文字框唤起编辑态。

**Non-Goals:**
- 不引入数十兆的深度学习重型通用图像修复大模型（保持轻巧极速与纯本地零内存膨胀）；对于极复杂复杂自然风景图，支持边缘融合保底。
- 不做完整排版富文本软件，专注于高频的单行/段落文本数字篡改与修改。

## Decisions

### 1. 轻量化边缘均值采样与色彩双线性感知填充 (Content-Aware Inpainting)
- **决定**：对于常规界面截图（IDE代码、表格、文档、网页），文字区域向外扩展 2~3 像素作为背景采样带。计算采样带上下左右四条边的平均色与渐变向量，使用双线性色彩插值生成修复纹理。
- **收益**：纯 C++ 实现仅约 60 行代码，零第三方库依赖，单图元擦除修复耗时不到 1ms，边缘过渡完全看不出接缝。

### 2. 前景/背景颜色聚类分离 (Color Separation)
- **决定**：统计包围盒内部所有像素在 RGB 空间的色彩距离分布。以边缘修复色作为背景色基准，内部距离背景色欧氏距离最远且占比最高的一簇像素平均值，即为原文字的原始真实颜色。
- **收益**：避免用户手动吸管取色，自动继承与原图一致的字体颜色。

### 3. 基于现有 InPlaceTextEditor 原地嵌入与复用
- **决定**：直接将现有的 `InPlaceTextEditor` 悬浮组件精准定位到被擦除的包围盒位置，初始填入原识别出的文本，并将字号、文本颜色与背景填充实时联动。
- **收益**：最大化复用现有成熟组件，支持中文输入法平滑呼出、Enter 提交、Esc 取消。

## Risks / Trade-offs

- **[复杂自然纹理背景修复瑕疵]**：如果文字位于自然风光、照片等高频噪点纹理上，简单的插值填充无法还原复杂树叶或建筑物纹理。
  - *缓解措施*：提供羽化（Feathering）边缘渐变滑块；若用户需要极精细打理，可配合自由画笔或克隆图章微调。
- **[系统字体库差异]**：原截图可能使用了特殊未安装字体。
  - *缓解措施*：默认优先使用 `Microsoft YaHei` 与 `Segoe UI`（覆盖 90% 界面），并在原地文本编辑器旁提供快捷字体族切换微调下拉框。
